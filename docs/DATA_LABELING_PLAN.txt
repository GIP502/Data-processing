# Data Labeling / 데이터 분류 기능 기획서

## 1. 기능 개요

Data Labeling은 여러 개의 Excel 파일을 한 번에 불러온 뒤, 미리 설정된 Process에 따라 각 파일을 자동으로 분류하고 필요한 데이터를 추출하여 사용자가 최종 처리 전에 검토하는 화면이다.

이 화면의 핵심 목적은 복잡한 편집이 아니라 다음 4단계를 빠르게 수행하는 것이다.

**파일 일괄 입력 → 자동 분류/추출 → 오류 및 결과 확인 → 처리 실행**

사용자는 정상적으로 처리된 파일은 별도로 조작할 필요가 없으며, 문제가 있는 파일만 확인하고 수정한 후 전체 처리를 실행할 수 있어야 한다.

---

# 2. 기본 사용 흐름

## STEP 1. Process 선택

화면 상단에서 사용할 Process를 선택한다.

예:

`Process : 월간 매출 데이터 정리 ▼`

Process가 선택되면 해당 Process에 저장된 아래 규칙이 자동 적용된다.

- 파일 분류 규칙
- 데이터 추출 규칙
- 데이터 계산 규칙
- 출력 항목
- 오류 판정 기준

기본 Process가 지정되어 있다면 화면 진입 시 자동 선택할 수 있다.

---

## STEP 2. 파일 입력

사용자는 여러 개의 Excel 파일을 한 번에 입력할 수 있다.

입력 방식:

- Drag & Drop
- 파일 선택 버튼
- 여러 파일 동시 선택

화면 중앙에는 큰 Drop Zone을 배치한다.

예:

**Excel 파일을 여기에 끌어다 놓으세요**

또는

**[ 파일 선택 ]**

지원 파일 형식 예:

- `.xlsx`
- `.xls`
- 필요 시 `.xlsm`

파일을 추가하면 별도의 실행 버튼 없이 자동 분석을 시작한다.

---

# 3. 파일 자동 분석

파일이 들어오면 Process에 따라 자동으로 다음 작업을 수행한다.

### 3.1 파일 분류

Process Builder에서 설정한 규칙에 따라 파일 종류를 판단한다.

예:

`ABC_main_2026.xlsx`

→ **Main**

`ABC_formation_2026.xlsx`

→ **Formation**

분류 기준은 Process Builder에서 이미 정의되어 있기 때문에 Data Labeling 화면에서는 결과만 보여준다.

---

### 3.2 데이터 추출

각 분류에 설정된 규칙에 따라 필요한 데이터를 자동으로 가져온다.

예:

Process 설정:

`Sheet1 C5 → Sales`

`Sheet1 D5 → Quantity`

`Sales / Quantity → Unit Price`

Data Labeling 화면에서는 다음과 같이 결과가 표시된다.

| File | Type | Sales | Quantity | Unit Price |
|---|---|---:|---:|---:|
| File_A.xlsx | Main | 10,000 | 5 | 2,000 |

즉 사용자는 Excel 파일을 직접 열어보지 않고도 필요한 정보를 한 화면에서 확인할 수 있다.

---

# 4. 메인 파일 목록

Data Labeling 화면의 중심은 **파일 목록 Table**이다.

각 행은 Excel 파일 하나를 의미한다.

예:

| 상태 | 파일명 | 분류 | 추출값 1 | 추출값 2 | 추출값 3 |
|---|---|---|---|---|---|
| ✓ | ABC_main.xlsx | Main | 100 | 20 | 5 |
| ✓ | DEF_main.xlsx | Main | 120 | 30 | 4 |
| ⚠ | GHI.xlsx | 미분류 | - | - | - |
| ! | JKL_main.xlsx | Main | 오류 | 15 | - |

Process마다 추출 항목이 다르기 때문에 오른쪽 열은 선택된 Process에 맞게 자동 생성한다.

---

# 5. 파일 상태

각 파일에는 처리 상태가 표시된다.

기본적으로 다음 상태를 사용한다.

### 정상

`✓ 정상`

분류와 데이터 추출이 모두 정상적으로 완료된 상태.

별도 사용자 조작 없이 바로 처리 가능하다.

---

### 확인 필요

`⚠ 확인 필요`

자동 처리는 되었지만 사용자가 확인하는 것이 필요한 상태.

예:

- 두 개 이상의 분류 조건을 동시에 만족
- 일부 값이 비어 있음
- 예상 범위를 벗어난 값
- Process에서 확인 대상으로 지정된 조건

---

### 미분류

`? 미분류`

어떤 분류 조건에도 해당하지 않는 파일.

사용자가 직접 분류를 지정할 수 있다.

예:

`분류 : [ 선택 ▼ ]`

---

### 오류

`! 오류`

정상적으로 데이터를 읽을 수 없는 상태.

예:

- 지정한 Sheet 없음
- 지정한 Cell 없음
- 잘못된 Excel 파일
- 수식 계산 오류
- 숫자가 필요한 위치에 문자열 존재
- 파일 손상
- 암호화된 파일

오류가 발생해도 전체 작업이 중단되면 안 된다.

오류가 발생한 파일만 별도로 표시하고 나머지 파일은 계속 분석한다.

---

# 6. 필터 기능

파일이 많아질 수 있기 때문에 상태별 필터를 제공한다.

상단에 다음 버튼을 배치한다.

**전체 128**

**정상 120**

**확인 필요 3**

**미분류 4**

**오류 1**

예:

`[ 전체 128 ] [ ✓ 정상 120 ] [ ⚠ 확인 3 ] [ ? 미분류 4 ] [ ! 오류 1 ]`

사용자가 `오류 1`을 누르면 해당 파일만 표시된다.

이 기능을 통해 수백 개의 파일을 넣더라도 문제가 있는 파일만 빠르게 확인할 수 있다.

---

# 7. 사용자 수정

자동 처리 결과는 최종 처리 전에 수정할 수 있다.

## 분류 수정

자동 분류된 결과가 잘못되었거나 미분류된 경우 사용자가 직접 변경할 수 있다.

예:

`분류 : Main ▼`

선택 가능한 값은 해당 Process에서 만든 분류 목록이다.

---

## 추출값 수정

추출된 데이터가 잘못된 경우 Table에서 직접 수정할 수 있다.

예:

기존:

`Sales : 15000`

사용자 수정:

`Sales : 16000`

수정된 값은 시각적으로 표시한다.

예:

`16000 ✎`

또는 셀 배경을 약하게 강조한다.

이를 통해 자동 추출값과 사용자가 수정한 값을 구분할 수 있다.

---

# 8. 파일 상세 확인

목록에서 특정 파일을 클릭하면 우측 또는 하단에 상세 패널을 표시할 수 있다.

예:

## File Detail

**파일명**

`ABC_main_2026.xlsx`

**분류**

`Main`

**상태**

`✓ 정상`

**추출 데이터**

Sales  
`10,000`

Quantity  
`5`

Unit Price  
`2,000`

필요한 경우 원본 위치도 표시할 수 있다.

예:

`Sales`

`10,000`

`Source : Sheet1!C5`

이를 통해 문제가 있을 때 어떤 위치에서 데이터를 가져왔는지 바로 확인할 수 있다.

---

# 9. 오류 상세 표시

오류가 발생한 경우 단순히 `Error`만 표시하지 않고 원인을 보여준다.

예:

### File_A.xlsx

**오류**

`Sheet "Summary"를 찾을 수 없습니다.`

설정된 위치:

`Sheet 2 / C15`

또는

**계산 오류**

`Quantity 값이 0이므로 Sales / Quantity 계산을 수행할 수 없습니다.`

사용자가 오류 원인을 바로 이해할 수 있는 메시지를 제공해야 한다.

---

# 10. 파일 관리

파일 목록에서 다음 기능을 제공한다.

- 파일 추가
- 선택 파일 삭제
- 전체 파일 삭제
- 파일 다시 분석
- 특정 파일 분석 재실행

예:

`[ + 파일 추가 ]`

`[ 선택 삭제 ]`

`[ 다시 분석 ]`

---

# 11. 처리 가능 여부

화면 하단에는 현재 작업 상태를 요약한다.

예:

**128개 파일**

`정상 123 · 확인 필요 2 · 미분류 2 · 오류 1`

그리고 우측에 핵심 버튼을 배치한다.

**[ 처리하기 ]**

---

# 12. 처리 버튼 동작

`처리하기`를 누르면 현재 확인된 분류 및 추출값을 기준으로 최종 처리한다.

정상 파일만 존재하면 바로 실행한다.

문제가 있는 파일이 존재하면 상황에 따라 안내한다.

예:

**3개의 파일에 확인이 필요합니다.**

- 미분류 2개
- 오류 1개

Process 설정에 따라:

- 오류가 있으면 처리 불가
- 정상 파일만 처리
- 사용자 확인 후 계속 처리

등의 방식을 선택할 수 있다.

기본값은 **중대한 오류 또는 미분류 파일이 있으면 처리 전에 사용자에게 알려주는 방식**이 적절하다.

---

# 13. 처리 완료

처리가 완료되면 Result 화면으로 이동한다.

흐름:

**Data Labeling**

↓

**처리하기**

↓

**Result**

Result 화면에서는 Data Labeling에서 확정된 결과만 사용한다.

---

# 14. 추천 화면 구성

전체 화면은 크게 다음과 같이 구성한다.

### 상단

`Data Labeling`

`Process : [ Monthly Process ▼ ]`

오른쪽:

`+ 파일 추가`

---

### 상태 영역

`전체 128`

`정상 120`

`확인 필요 3`

`미분류 4`

`오류 1`

---

### 중앙

파일 목록 Table

| 상태 | 파일명 | 분류 | A | B | C | ... |
|---|---|---|---|---|---|---|

화면 대부분을 이 Table이 차지한다.

---

### 우측 패널

선택된 파일 상세 정보

- 파일 정보
- 분류
- 추출 결과
- 원본 위치
- 오류 내용

필요 없을 때 접을 수 있다.

---

### 하단

왼쪽:

`128 files loaded`

오른쪽:

`[ 처리하기 ]`

# 15. UX 핵심 원칙

Data Labeling 화면은 **설정 화면이 아니라 검수 화면**이다.

따라서 기능을 많이 노출하기보다는 다음 원칙을 유지한다.

### 정상 파일은 최대한 건드리지 않는다.

100개의 파일 중 97개가 정상이라면 사용자는 97개를 일일이 확인할 필요가 없어야 한다.

### 문제 파일을 눈에 띄게 보여준다.

사용자의 실제 작업은 대부분:

**미분류 / 오류 / 확인 필요**

파일을 확인하는 것이다.

### 수정은 바로 할 수 있어야 한다.

다른 설정 화면으로 이동하지 않고 현재 화면에서:

- 분류 변경
- 추출값 수정

이 가능해야 한다.

### 처리 전 반드시 확인 단계가 존재한다.

파일을 입력했다고 바로 최종 파일을 만들지 않는다.

**자동 분석 → 검수 → 처리**

의 단계를 유지한다.

---

# 16. 전체 기능 흐름

최종적으로 Data Labeling은 다음 구조다.

**Process 선택**

↓

**Excel 파일 여러 개 입력**

↓

**자동 파일 분류**

↓

**자동 데이터 추출 및 계산**

↓

**파일 목록 생성**

↓

**정상 / 확인 필요 / 미분류 / 오류 표시**

↓

**문제 파일 확인**

↓

**필요 시 분류 또는 데이터 수정**

↓

**처리하기**

↓

**Result 화면으로 이동**

---

# 17. 핵심 컨셉 한 줄

> **“수백 개의 Excel 파일을 넣으면 자동으로 분류·추출하고, 사용자는 문제가 있는 파일만 확인한 뒤 한 번에 처리한다.”**

이것이 Data Labeling 화면의 가장 중요한 UX 컨셉이다.
