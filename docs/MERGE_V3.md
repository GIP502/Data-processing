# Process Builder v3 병합 검토 · 2026-10-03

검토 대상: 사용자가 제공한 Window-Starter-ProcessBuilder-v3.zip과 기존 Labeling/Result 완성본.

판정: 호환 연결을 보완하는 선택적 병합의 성공 가능성을 약 95%로 판단해 진행했습니다. 이는 파일/공개 계약/데이터 흐름 비교에 따른 공학적 추정이며 통계적으로 측정한 확률이 아닙니다.

## 가져온 변경
- process-builder.js, process.css: 세 단계와 중앙 편집 / 오른쪽 미리보기.
- process-core.js: 파일명 조각, 추가 비교 연산, 시트 이름/순서, 시작 주소와 동적 끝, 목록 방향별 계산, 표의 출력 열 선택.
- 수정본 규칙 테스트는 process-v2.test.cjs로 추가했습니다.

## 발견한 충돌과 처리
- 수정본 app.js/index.html은 Labeling/Result가 아직 빈 창인 버전입니다. 기존 조립/스크립트/전체 창 기능을 사용했습니다.
- 수정본 Process Builder는 저장소에 직접 쓰지만 현재 Labeling은 ProcessStore 알림이 필요합니다. 공유 저장 계약으로 연결했습니다.
- 수정본 규칙은 version 2, 기존 저장 목록은 version 1만 받았습니다. 같은 저장 키에서 두 버전을 정규화해 읽고 ID/기본 선택을 유지합니다.
- 수정본 evaluate에는 수동 분류/수정값 인자가 없습니다. 현재 공개 evaluate(book,config,options)를 이식했습니다.
- 수정본에서 빠진 검수 기준/처리 정책 UI, Excel 오류 셀 판정, 숫자 오버플로 검사를 복원했습니다.
- 기존 끝 위치가 빈칸인 행/열 추출을 새 last-data로 변환하면 일부 빈값 행이 사라질 수 있습니다. sheet-end 호환 모드로 이전 시트 경계를 유지했습니다.
- v3 시작 주소/시트 순서/동적 범위에 맞춰 Labeling 원본 위치 안내를 보완했습니다.
- 수정본 파일 리더는 XLS를 지원하지 않으므로 기존 로컬 SheetJS 리더와 XLS/XLSX/XLSM 지원을 유지했습니다.
- 기본 HTML/배경/브랜드 이미지/Windows 실행기/창 애니메이션과 Result 내보내기 코드는 기존 버전을 유지했습니다.

## 확인 결과
52개 규칙 테스트 통과: 기존 검수/계산/애니메이션/결과 출력, 수정본 v2 법칙, v1 범위·검수·정책·기본 ID 보존, 새 동적 표와 수동 수정 연결, 오류/오버플로, 저장소 알림.

실제 Edge 검사 통과:
- 기존 8개 XLS/XLSX/XLSM·손상 파일의 분류/값 수정/확인/부분 처리 → Result.
- Result 실제 클립보드 및 XLSX/CSV 다운로드 후 내용 확인, 선택/페이지/파일별 시트/지정 위치.
- v3 UI에서 파일명 조각·시트 순서·동적 표·계산·출력 열·검수 정책 설정, 저장 즉시 Labeling 목록 연결.
- 실제 Excel 예시 미리보기 → 확인 전 처리 차단 → 확인 후 결과 생성 → 범위 수정 후 다시 처리.

OS 저장 대화상자 자체와 작업 관리자 프로세스 아이콘 표시는 이번 병합 검사 범위에 포함하지 않았습니다. 해당 구현은 기존 버전 그대로입니다.
